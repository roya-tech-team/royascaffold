# Initial Build Workflow

## Goal

Build a new system through layered knowledge and dependency-ready vertical slices.

## Sequence

1. **Route:** classify consequence, uncertainty, judgment, artifact mode, adapters, gates,
   and review authority.
2. **Discover:** inspect sources first; ask only material questions; record findings,
   decisions, assumptions, priorities, unacceptable outcomes, and owners.
3. **Business:** write product brief/outcomes/capabilities/scope/glossary. Do not require
   a document named BRD when another approved business owner serves the same contract.
4. **Quality contract:** approve the QDC seed: audience, priority order, `must/should/may`,
   foundation/optional scope, content/data policy, thresholds, and proof authority.
5. **Interpret references:** create RDRs for influential visual, behavioral, document,
   or data sources so decisions survive session loss.
6. **Requirements/domain:** write observable requirements/NFRs and model concepts,
   invariants, and complex workflows.
7. **System design:** create system map and project-specific architecture, experience,
   content/data, quality, operations, pattern decisions, and capability roadmap.
8. **Solution review:** run SQR at the routed authority. Fix findings in their owners;
   only `pass` or satisfied non-blocking conditions may proceed.
9. **Select next slice:** fully design only the next dependency-ready foundation slice.
10. **Compile:** create foundation-first execution tasks and exact Context Packs from
    approved decisions.
11. **Readiness review:** run IRR consumer test; set `ready` only when no material
    invention, contradiction, stale input, conflict, or silent truncation remains.
12. **Deliver:** implement one task, verify against the QDC with source-bound evidence,
    reconcile durable truth to Main, optionally release.
13. **Repeat or stop:** Main and generated Next Up remain sufficient to resume without
    the original conversation.

## Gates

- business language/scope/workflow approval;
- system design/roadmap approval;
- per-slice design and execution-ready approval based on risk;
- solution-quality and implementation-readiness gates based on judgment/consequence;
- verification and reconciliation gates.

## Stop rule

Never materialize or implement the whole system in one context. Stop after each reconciled slice or explicit pause.
