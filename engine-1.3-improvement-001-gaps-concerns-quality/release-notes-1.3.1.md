# RoyaScaff 1.3.1 Release Notes

**Status:** implemented engine candidate; contract acceptance is complete and the
controlled low-model product outcome benchmark remains pending.

## Purpose

Raise lower-model first-implementation quality by making material product, reference,
experience, content, pattern, and quality decisions explicit before code. Verification
remains the closing assurance loop rather than the product-discovery mechanism.

## Added

- decision-oriented discovery and quality-bar authority;
- QDC, RDR, pattern, SQR, and IRR contracts/templates/schemas;
- reference analysis and two pre-code review skills;
- consequence × uncertainty × judgment routing and adaptive artifact modes;
- adapter manifests/composition/provenance;
- foundation-first task and exact Context trace rules;
- source fingerprints, evidence freshness, and adjudicator authority;
- generated quality/readiness/evidence/adapter views;
- legacy-compatible/transition/strict adoption modes;
- dependency-free Node contract tests.

## Preserved

- Main as durable truth, Change as active delta, and Context as generated view;
- layered knowledge, exact IDs, adaptive workflows, implementation, verification,
  release, and reconciliation;
- technology-neutral core and optional adapters;
- dependency-free Node runtime and existing commands.

## Known limits

- CLI validation does not judge aesthetic quality, semantic coherence, or stakeholder
  satisfaction.
- Source fingerprint detection is deterministic for declared local files; external or
  manual evidence needs an equivalent stable source identity and reviewer discipline.
- The engine improves the inputs and gates for low models but cannot guarantee an A for
  every model/task. Controlled model benchmarks must report first pass and final result
  separately.
- Evolutionary requirement history/experiment rollback and broader human/AI engine UX
  remain separate improvements.
