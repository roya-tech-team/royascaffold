# Architecture Template

Record system style, application/deployment boundaries, modules/contexts, allowed dependency directions, sync/async communication, data ownership, cross-cutting security/config/logging/caching, testing boundaries, runtime/deployment topology, exceptions/ADR links, and component diagram.

Describe the actual project; adapter defaults are not architecture facts.

For each material choice link a `PAT-*` record with problem/forces, selected adapter
guidance, choice and fit, alternatives rejected, constraints, failure modes, affected
components/contracts, criteria, tasks, and validation. Architecture mechanisms must
trace to product/quality outcomes but cannot replace them.
