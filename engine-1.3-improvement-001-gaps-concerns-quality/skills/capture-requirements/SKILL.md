# Capture Requirements

## Procedure

1. Inspect prompt, Main, Change, profile, references, inventory, and selected adapters
   before asking anything.
2. Extract sourced `FND-*`, already-supplied `DEC-*`, and unknowns with confidence.
3. Separate missing facts from stakeholder decisions. Ask only when a default could
   materially alter outcome, scope, experience, content, technology, or quality.
4. For each question give the recommendation, alternatives, tradeoffs, deferral impact,
   and decision authority. Do not make business users choose derivable implementation
   details.
5. Record the answer, an authority-approved `ASM-*`, or a blocker.
6. Calibrate outcome, audience, priority order, `must/should/may`, foundation/optional
   scope, unacceptable outcomes, content/data policy, threshold source, and review
   authority as the QDC seed.

Write only business/requirements/QDC deltas. Every criterion describes an observable
outcome and proof method. A model may recommend a quality threshold with rationale but
cannot approve its own ungrounded material bar. Existing changes ask only true deltas
from Main.
