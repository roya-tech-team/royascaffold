# Change Workflow

Use for new/changed behavior, contracts, data, architecture, dependencies, migrations, or knowledge-only decisions.

1. Capture outcome, source, non-goals, baseline, known decisions, and desired after-state
   in `changes/active/<id>/change.md`.
2. Route consequence/uncertainty/judgment, artifact mode, adapters, gates, and authority;
   check dependencies and active ownership conflicts.
3. Analyze every layer and QDC/RDR/pattern/evidence owner as changed, referenced,
   inherited, unchanged, stale, or not-applicable.
4. Run delta discovery only for material decisions not already owned by Main. Approve
   QDC delta and influential reference decisions.
5. Draft after-state deltas for requirements/workflows/design/experience/content/data/
   implementation/quality/operations and select material patterns.
6. Run routed SQR; fix source artifacts and repeat until passed.
7. Compile foundation-first executable tasks, evidence authority, rollout/rollback, and
   exact Context Packs.
8. Run routed IRR consumer test; set `ready` only after blockers and stale inputs close.
9. Implement only approved tasks. Missing material or new public/design scope returns
   to its owning phase instead of being invented.
10. Verify QDC/requirements with replayable source-bound evidence and routed authority.
11. Preview reconciliation, promote durable decisions to their Main owners, archive
    QDC/RDR/review/context provenance correctly, regenerate, and validate.
12. Release/monitor if applicable; archive and close.

Knowledge-only changes omit code tasks/evidence and use semantic/traceability review
appropriate to the changed facts. Compact low-judgment changes may embed QDC/SQR/IRR
sections in `change.md`; they do not omit triggered material decisions.
